# 0034. `goronation vault reset` は、Vault の中身を壊すだけで、読まず、記録を残す (M2)

- 状態: 採用
- 日付: 2026-09-30
- 関連: [Issue #1](https://github.com/nananek/goronation/issues/1) (「Vault (Passkey PRF)」)、ADR 0031・0033

## 状況

PRF 出力が漏れた・passkey を全部失った・Vault が壊れたとき、鍵の階層 (ADR 0033) の内側からは、回復できない。ラップは追加だけで、salt も回さないので、失効の手段が、別に要る。

## 決定

1. **`goronation vault reset` を、シェルから実行できる、唯一の最終手段にする。** 呼べるのは、デーモンと同じ OS ユーザーのシェルだけ。web の経路 (HTTP・WebSocket) からは、呼べない。
2. **壊すだけ。** ラップ・暗号化した項目・Vault の ID を、消す。PRF 出力・本体鍵・保管した値は、使わない・読まない。解錠していなくても、実行できる。
3. **reset の後は、空で初期化前の Vault になる。** 次の解錠の儀式 (ADR 0035) で、新しい ID・新しい本体鍵を作り、そのとき使った passkey のラップを、最初の 1 つにする。
4. **Vault の外は、変えない。** web のログインの passkey (`<state>/credentials/webauthn`) は残る。Vault の中身は、全部作り直せるものだけを置く (資格情報は `goronation auth` で入れ直す・GPG の鍵は作り直す・ログインはやり直す)。GPG の失効証明書は、鍵の作成時に、1 回だけ提示する (任意)。
5. **監査の記録を残す。** 時刻・event (reset)・実行した OS ユーザー・消した Vault の ID を、Vault の追記だけの記録 (`<state>/vault/audit.log`・0600・`O_APPEND`) に書く。秘密は書かない。reset は、この記録を消さない。
6. **対話で確認する。** 端末でなければ、実行しない。確認では、消す Vault の ID の先頭を入力させる。
7. **デーモンが解錠済みなら、reset は、先に施錠させ、確認できなければ失敗する。** 古い本体鍵が、どのプロセスのメモリにも残らないことを、完了の条件にする。方法は、実装の PR で決める。

## 帰結

- reset の前のファイルの写し (バックアップ・スナップショット) は、消せない。その写しと、漏れた PRF 出力があれば、復号できる。reset は、鍵を回さず、Vault を作り直すだけである。
- 監査の記録は、Vault の外の、後の監査ログ (M2 の別の項目) ができるまで、この 1 つが正になる。
- 保管した値を、reset が読まないので、reset の実行が、秘密の漏れの経路にならない。

## 代替案

- web から reset できる: 乗っ取られたセッションが、Vault を壊せる (可用性の攻撃)。Issue は、シェルからと決めている。
- 中身を消さず、ラップだけを消す: 暗号文が残り、漏れた PRF と組み合わさると、復号できる。
- 確認なしで実行する: 誤操作で、全部が消える。
