# 0011. 会話の状態機械と、未決の権限要求の保持 (M1.5)

- 状態: 採用
- 日付: 2026-09-29
- 関連: [Issue #1](https://github.com/nananek/goronation/issues/1) (M1.5・設計ルール 10)、ADR 0009・0010、`cmd/internal/chat` の doc

## 状況

M1.5 は、人間の指示と権限の承認を、エージェントに返す。承認は、エージェントの出力 (敵対入力) が作る要求に対する応答で、取り違え・偽造・洪水が本スコープの中心のリスク。ADR 0009 は、リングバッファが溢れると、未決の要求も押し出されることを限界として残した。

## 決定

1. **状態は idle・turn・awaiting_permission (turn 中で未決あり)・closed。** `Send` は idle のときだけ受ける (ほかは 409。queue・steer・中断は M2)。text は空を拒否し、64 KiB まで。
2. **承認は、要求 ID に束縛し、1 回だけ有効。** クライアントが送れるのは request_id と outcome (allow_once・reject_once) だけ。許可する input は、Stream が要求時に保持した値だけから作る。未決でない ID は 404、応答済みの ID は 409。
3. **同時に待つ要求は 8 件まで。** 超えた要求と、ターンの外に来た要求は、claude に拒否を返し、by=policy で決着させる (画面には出す)。
4. **未決の permission.requested は、Hub に固定する。** リングから溢れても、新しい購読者の Snapshot の先頭に含め (Seq 順)、決着したら外す。固定は 16 件まで。
5. **終了・Stop・書き込みの失敗で、未決は全部失効する** (by=policy・cancelled。以後の承認は 404)。書き込みに失敗したら、Stream の状態は進んでいるので、やり直さず会話を終える。タイマーによる失効・自動停止は持たない (ADR 0009)。
6. 同じ error の連続 (上限超過の洪水) は、最初の 1 件だけを配る (seq は欠ける)。

## 帰結

- 会話は 1 回の起動に紐づく。起動をまたぐ request_id は無効。
- Write は、Mutex を持ったまま呼ぶ。呼び手 (PR④) は、有界のキューに積むだけにする。
- 出力が本物のフレームかは確かめられない (ADR 0010)。この状態機械は、偽造された要求・撤回を、見分けられない。
- 内容ハッシュの束縛は M2。

## 代替案

- リングを大きくする: 上限を上げても、洪水で溢れる。固定なら、件数だけが上限になる。
- 上限を超えた要求を黙って捨てる: claude が応答を待ち続ける。拒否を返す。
