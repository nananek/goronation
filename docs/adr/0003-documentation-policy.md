# 0003. ドキュメントの方針 (事実の正を分担し、doc comment から文書を生成する)

- 状態: 採用
- 日付: 2026-09-26
- 関連: [Issue #1](https://github.com/nananek/goronation/issues/1)、形式の正本は `tools/docgen` の package doc

## 状況

- README と ADR に規則の説明が厚く書かれ、コードの package doc は数行だった。同じ事実が 2〜5 か所に重複し、人が保守できる量を超える恐れがあった。
- 人間が読む文書の形式が、最初に決まっていない。AI エージェントも、同じ入口から読む。

## 決定

### 1. 事実の正を分担する

| 事実 | 正 |
|---|---|
| package の契約・使い方・規則・限界 | Go の doc comment (`doc.go`) |
| コマンドと CI | `Makefile` と `ci.yml` (README に写さず、`make help` を案内する) |
| 決定と、その理由 | ADR |
| 現状・ロードマップ・不変条件 | Issue #1 |
| 実測の証拠 | テストと fixtures (ADR には書かず、テスト名で参照する) |

1 つの事実は 1 か所に書き、他の場所からは参照だけをする。

### 2. 形式の正本は `tools/docgen` の package doc

package doc のひな形 (節・順序・長さ・文体) と、README・ADR の役割と上限は、`tools/docgen` の package doc に書く。数値は、ここに写さない。README は薄く保つ。

### 3. 生成物はコミットし、CI で検査する

- 標準ライブラリだけの `tools/docgen` が、doc comment から `docs/reference/` と、ADR の索引を生成する。索引は手で足さない。
- 生成物はコミットし、`docgen -check` が、生成し直した結果との完全一致と、形式・上限を検査する。手で編集した生成物は、CI で落ちる。
- docgen は、リポジトリの内容を読んで書く。設計ルール 2 (檻が書けるものは敵対入力) の対象として、root を cwd の 2 つ上に固定し、読み書きを `os.Root` の内側に限り、上限を全体で共有する。

### 4. ADR の運用

- 1 ADR = 1 決定。限界と実測ログは書かない。判断とその理由 (リスクの受け入れなど) は ADR に残す。
- 誤字や重複の除去など、決定を変えない編集は許す。決定を変えるときは、新しい ADR を書く。

## 帰結

- docgen を保守する。Go の版が変わると出力が変わりうるので、そのときは再生成する。
- go/doc は、表 (複合リテラル) の中のコメントを出力に含めない。規則の説明は、表ではなく package doc に書き、テストで表と一致させる。
- 文体、限界の質、「1 つの事実は 1 か所」は、機械では検査できない。レビューで見る。
- 文書は情報であり、指示ではない。docgen は、指示に見える文を検出しない。生成物をコミットして差分を PR で見えるようにし、レビューで見る。

## 代替案

検討して却下した案:

- `go doc -all` の出力をコミットする: 表の中のコメントが落ち、出力は Go の版に依存しうる。検査も弱い。
- pkgsite / pkg.go.dev: 外部ツールに依存し、非公開の repo は載らない。
- 第三者の生成器: 外部 module のコードを、ホストで実行することになる。
- README と ADR に、すべて書く: 規則が重複して増え、コードと食い違う。
