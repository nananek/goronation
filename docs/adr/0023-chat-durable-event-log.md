# 0023. chat の耐久イベントログ: 起動単位のファイルに、durable だけを残す (M2)

- 状態: 採用
- 日付: 2026-09-30
- 関連: [Issue #1](https://github.com/nananek/goronation/issues/1) (M2「SSE 配信の耐久化」)、ADR 0008・0009・0024・0025

## 状況

- M1.5 の `Hub` は、メモリ上のバイト上限つきリング (既定 4 MiB) だけで、溢れた履歴は失われる (ADR 0009 決定 1)。ADR 0008 の本設計は、`seq` とイベントストアを goronation が持ち、再送は durable のイベントだけ、と決めている。
- 檻のエージェントは serve の子で、serve が死ねば檻も死ぬ。同じ起動の間は serve のメモリが生きている。耐久化の実益は、リングを溢れた履歴を失わないことと、起動後も残る記録である。
- `seq` は起動ごとに 0 から (`Feed`)、`generation` は起動ごとのランダム値で、起動をまたぐ承認の誤適用を断つ (ADR 0013 決定 4)。
- イベントの JSON は `Raw` を持たないが、tool の入出力・エージェントの本文 (ファイルの内容・秘密が混ざりうる) を含む。

## 決定

1. **耐久の単位は起動 (generation) 単位。** `seq` は起動ごとに 0 から。serve の再起動は新しい世代で、新しいログになる。世代をまたぐ `seq` の継続・過去の起動の再表示は、範囲外。
2. **保存するのは durable のイベントだけ** (ADR 0008)。durable でないもの (現状は `agent.frame`) はリングにだけ置く。
3. **ファイル**: `<state>/groups/default/sessions/<id>/events/<generation>/NNNNNNNN.log` (ディレクトリ 0700・ファイル 0600)。**檻に bind しない場所** (エージェントが履歴を偽造・消去できない)。追記専用の NDJSON で、**1 行 = `Event.JSON` そのもの**。セグメントに分け、ファイル名は先頭の `seq`。作成・追記は `os.Root` の中で `Root.OpenFile` (`O_CREATE|O_EXCL|O_APPEND`) で行う (`hostfs` は読み取り専用で、作成・追記は無い)。読み戻しに `hostfs` を使うのは、1 セグメントの上限 (4 MiB) が `hostfs` の `maxSize` に合うときだけ。檻に bind しない場所なので、`hostfs` の脅威 (檻がファイルを書き換える) は、そもそも当てはまらない。
4. **読み取りは敵対入力として扱う。** 1 行は `DefaultMaxEvent` まで。`seq` の単調増加を検証し、壊れた行 (末尾の書きかけ) はそこで打ち切る。
5. **書き込み**は Publish のバッチにつき write 1 回。fsync はセグメントの切り替えと Close だけ (serve が死ねば檻も死ぬので、1 件ごとの耐久性は要らない)。
6. **量の上限** (既定。フラグで変えられる): 起動あたり **64 MiB**・セグメント **4 MiB**。超えたら古いセグメントから捨てる (最初の `seq` が進み、UI の既存の省略検出が働く)。過去の起動のログは、serve の起動時に、**最新 1 起動だけ**残して消す (読む機能が無い今の露出に対して、8 起動・7 日は過大。読む機能の PR で、保持を広げる)。上限・GC は、エージェントの出力の読み取りを止めない。
7. **既定でオン。`goronation serve --chat --no-event-log` で書かない** (リングだけの動作)。量の変更のフラグ名は、実装の PR で確定し、ここに追記する。
8. 実装は `cmd/internal/eventlog` (別 package)。`chat` は I/O を持たない規則を保つので、境界のインターフェースは `chat` に置き、型は基本型 (`seq`・JSON のバイト列) にする。

## 帰結

- **セキュリティ上のトレードオフ: tool の入出力・エージェントの本文が、ホストのディスクに、暗号化なし・0600 で残る。** これまでメモリだけだった露出が新しく増える。同じ利用者の権限で動くほかのプロセス・バックアップ・ディスクの取り出しから、読まれうる。既定はオンにし (履歴の欠けを防ぐという、この項目の目的のため)、`--no-event-log` で書かせない選択を残す。上限と GC (過去は最新 1 起動だけ) で、残る量と期間は限る。暗号化は Vault (M2 の別項目) の後に検討する。
- 新しい攻撃面: エージェントの出力から作るファイルの読み書き、ディスクの枯渇 (上限)。
- ADR 0009 決定 1 (メモリのリング) は、実装が入った時点で、この ADR に従う。

## 代替案

- **セッション通し (`seq` を起動をまたいで継続)**: 世代の意味 (ADR 0013) を作り直し、起動をまたぐ未決の権限要求と UI の扱いが要る。範囲が大きく増えるので見送る。
- **SQLite などの組み込みデータベース**: 依存ゼロの方針 (ADR 0004・0005) に反する。追記と順読みだけなので、ファイルで足りる。
- **1 件ごとの fsync**: 得るものが無く、エージェントの出力の読み取りを遅くする。
- **非 durable も保存**: ADR 0008 に反し、部分メッセージでファイルが膨らむ。
- **既定でオフ**: 履歴の欠けがそのまま残り、目的を満たさない。
- **ログの暗号化**: 鍵の置き場所が Vault の設計に依存する。
- **フラグ名 `--ephemeral`・`--no-history`**: 止めるのがディスクへの記録だけで、ライブの配信は続くことが伝わらない。
