# 0048. UI の form・要約と詳細の表示と、承認の関門の移設 (M2)

- 状態: 採用
- 日付: 2026-10-01
- 関連: [Issue #1](https://github.com/nananek/goronation/issues/1)、ADR 0015・0016・0040・0041・0042・0046・0047、`cmd/goronation/assets/chat/`

## 状況

b-1 (ADR 0046・0047) で、権限の要求は要約 (`summary`)・詳細 (`details`)・`content_hash` を持ち、`form.requested` と `POST /form` が加わった。画面は、これを描かず、`input` だけを見せて承認させていた。form は描けず、claude の質問は答えられなかった。詳細・form の文は、どちらもエージェントが決める敵対入力で、人間の判断に出る。

## 決定

1. **承認の関門を、`input` から詳細に移す** (ADR 0016 決定 8 の対象を替える)。詳細があれば、許可できるのは、`details_truncated` でなく、全項目が切れていない (形が不正な項目・上限を超える項目数もない) ときだけで、詳細の枠は、決定 8 の見た範囲・時間の追跡を、そのまま受ける。詳細が無い・配列でない・空の要求 (旧い形) は、今までどおり `input` が関門。`details_truncated` の要求は、拒否だけ。生の `input` は、詳細があるときは畳んだ参考で、関門に使わない。
2. **詳細の見出しは偽造できない**: 見出し (`■ label`) は 1 行で、本文は全行を字下げして出す。label は、エージェントが決めたキーを含むので、厳しい印 (ADR 0015) を通す。
3. **form は、エージェントの文だけを `textContent` で出し、入力部品は `form.requested` の未決の項目からだけ作る**。「回答はエージェントに渡る (秘密は入力しない)」を常に出す。`password`・`file`・`textarea` は作らない。入力欄は `autocomplete=off`・`maxLength` つき。
4. **答えられない form は、取り消しだけ**: 知らない type・key の重複・空か長い key・value・上限超過・選択肢なし・request_id に印がある、のどれかで、部品を作らない。サーバーが拒否する形を、作らない。
5. **回答の key・選択肢の value は、生の値を持つ**。表示用の文字列でも DOM から読み戻した値でもない。回答は `Object.fromEntries` で作り、`__proto__` という key でも、プロトタイプを変えない。空の回答は省き、`custom` の値が選択肢と重複するときは送らない。
6. **`content_hash` は、受け取った生の値を、承認・回答にそのまま写す** (無ければ欄を付けない。検査・加工はしない。照合はサーバー。ADR 0046)。409 は、本文の `error` が `content_changed` なら「内容が違う (未決のまま)」、そうでなければ「決着済み」と、文を分ける。
7. **送信は、検証済みの世代つき・書き込み先は固定** (`/permission`・`/form`)。決着の表示は、`permission.resolved`・`form.resolved` を受けてから。request_id は、権限と form で名前空間・未決の上限を共有し、種類の違う決着は無視する。未決の form は、表示の上限で押し出さない。

## 帰結

- claude の AskUserQuestion に、画面から答えられる。承認は、要約と、全項目の詳細を見てから許可する。
- UI の上限は、spec/v0 の文字数 (rune) を、UTF-16 の単位で、切らない大きさにした。
- `RequireContentHash` を true にする判断は、実物で確かめたあと (別の判断)。

## 代替案

- 詳細を `input` の関門と別に残す: 2 つの関門が食い違うと、見せていない側を承認できる。
- 答えられない form の、読める部分だけを描く: 見せていないものに答えさせる。
- 回答のキーを、DOM の属性から読む: 表示用の文字列が、送る値と食い違う。
