# 0016. チャット画面の書く側: 送信・終了・権限の承認 (M1.5)

- 状態: 採用
- 日付: 2026-09-30
- 関連: [Issue #1](https://github.com/nananek/goronation/issues/1)、ADR 0011・0013・0014・0015、`cmd/goronation/assets/chat/`

## 状況

表示だけの画面 (ADR 0015) に、指示の送信・終了・権限の承認/拒否を足す。承認は、認証・認可の境界を動かす: 人間が見ている要求と、承認が適用される要求が、食い違ってはならない。エージェントの出力は敵対入力で、tool 名・title・input・request_id も、エージェントが決める。

## 決定

1. **書き込みは fetch の 1 か所** (`post`): 呼び先は `/s/{id}` + `/message`・`/permission`・`/stop` の固定 3 つだけ。Content-Type: application/json (Origin は同一オリジンのブラウザが付ける。PR⑥ の関門)。呼び先を、Go のテストが数える (動的な参照を見逃す静的検査の穴 (ADR 0015 の Limit) を、呼び先そのものの固定で補う)。
2. **送信欄**: 検証済みの hello を受けて接続が生きていて、ターン中でなく (turn.started〜turn.completed)、終了していない間だけ有効。200 の後は、次の turn.started を受けるまで無効 (二重送信を防ぐ)。失敗の status (400・403・404・409・413・415・502・504・通信の失敗) は画面に出し、入力は消さない。64 KiB 超は送らない。`Ctrl+Enter` でも送る。
3. **終了ボタン**: 2 回押しで `/stop` (押し間違いの防ぎ。4 秒で戻る)。
4. **権限ダイアログ**: `kind` が permission で `state` が pending の項目からだけ作る (ログの項目とは別の枠。項目の作り直しで消えない・入力途中の送信欄も消えない)。ボタンは input より上で、枠は高さを限ってスクロールする (巨大な input がボタンを押し出さない)。未決の件数を枠の外の見出しに出す。
5. **世代**: ダイアログは、見せた時点の `state.generation` (検証済み。32 桁の 16 進) の写しを持ち、それだけを `/permission` に入れる。接続が切れている間・世代が変わった後 (serve の再起動で、表示ごと作り直す)・終了後は、送らない。hello の前の Event は使わない。世代の無い hello の接続では、ダイアログを出さない。
6. **request_id は生の値を返す**: 表示用 (印つき・切った) の値ではなく、Event の生の `request_id` を持ち、そのまま返す (見えない文字だけが違う 2 つの要求が、同じ ID に見え、表示した要求と別の要求を承認させる、のを防ぐ)。見えない文字・300 文字超を含む ID の要求は、**許可できない (拒否だけ)**。input を切った要求も、許可できない (拒否だけ)。長さ 1,000 超の ID の要求は扱わない。request_id は、項目 (JS のオブジェクト) からクロージャで使い、DOM の属性から読み戻さない。
7. **応答の扱い**: 押したら、そのダイアログのボタンを無効にする。200 の後も、`permission.resolved` を受けるまで無効のまま (決着の表示は、そのイベントを受けた項目からだけ。自分のクリックでは、承認済みと出さない)。409・404 は「すでに決着済み」として有効に戻さない。ほかの失敗は、もう一度押せる。
8. **見せていない input は許可させない** (レビューの B1・B2): input の表示は、打ち切り付きの直列化 (`boundedJSON`。JSON.stringify と同じ形で、長さ 4,000 文字・深さ 40 で止める) で作る。例外 (深い入れ子で JSON.stringify が投げる) を「空の input」に化けさせず、CPU も深さの 2 乗に膨らませない。打ち切った・input が無い・オブジェクトでない要求は、許可できない。**枠 (高さを限る) にスクロールが要る input は、末尾までスクロールするまで許可できない** (字数が上限以内でも、危険な内容を末尾に置ける)。押した時点でも見直す。理由を枠に出す。
9. **表示の見せ方**: `title` は「エージェントの自己申告・未検証」の印つき。拒否を先 (左) に置き、許可は離す。turn.started を取りこぼしても、繋ぎ直し (hello) で送信待ちを解除する。
10. **開いた `<details>`** は、項目の更新で閉じない (N-C)。

## 帰結

- 内容ハッシュ束縛 (M2) が無いので、承認が適用されるのは「request_id が一致する、その起動の、保持した input」であり、画面の表示とサーバーの保持は、同じ Event から来る。
- 見えない input・ID の要求は、拒否だけにできる (許可できない)。エージェントは、その要求で待ち続ける (手動の「終了」で止める)。
- 実ブラウザで、ボタンが画面内・最前面にあること、無効なボタンが送らないことを確認した (Firefox headless)。

## Limit (記録のみ)

- input を JS の値にして表示するので、大きな整数は丸まり (`12345678901234567890` → `...67000`)・キーの順が変わる (整数のようなキーが先)。実際の許可は生の input。M2 の内容ハッシュ束縛と合わせて扱う。
- 表示後にレイアウトが変わって (フォント・画面幅) 枠が溢れても、ボタンの見た目は変わらない (押した時点で見直して送らない)。

## 代替案

- 世代を DOM の属性・入力欄から読む: エージェント・画面の外から来る値を、承認に使うことになる。
- 表示用の ID を返す: 見えない文字で、別の要求を承認させられる。
- ボタンを押した時点で、承認済みと表示する: サーバーが拒否しても、承認されたように見える。
